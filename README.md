# Clan Clog Client

Send obtained item data to your Clan Clog submission API.
Clan Clog is an unreleased project, this RuneLite plugin is made in anticipation of its release.
Once it is released is will be an open source and self hostable website for clans.

## How to Use

1. **Submission endpoint URL** The full URL of your submission endpoint `https://your-clan.example/api/v1/runelite/submissions`
2. **Clan API key** Shared clan API key generated by the website host/clan owner/admin.
3. **Submission chat notification** Turn it off to hide  submission acceptance and error messages in the in-game chat.
4. Be a member of a clan, its name is matched to the configured clan name on the website.
While clan channel is joined the plugin also submits items from clan broadcasts in the name of the player triggering the broadcast.
5. Enable `Loot Tracker` plugin for full functionality, drops are matched to either chat messages or drops registered in the `Loot Tracker`

## Detection and evidence

See [DETECTION.md](DETECTION.md) for tables on how items are detected, detection routes, detection gaps.

- Only items present in the game's collection log cache are submitted.
- Evidence screenshot is sent to API for personally gained items, clan broadcast triggered submissions only send the triggering message.

## New items
The plugin reads collection log tabs, pages, item IDs and names from the game cache.
It does not use a fixed list of items or download a separate item list.

## Submission contract and retries

Each request is `POST multipart/form-data`:

| Field | Value |
| --- | --- |
| `username` | Logged in character name, or the clan broadcast's recipient |
| `clanName` | Primary clan name for personal drops and for broadcasts |
| `itemId` | Obtainable OSRS game item ID |
| `worldType` | JSON array of RuneLite world flags: the local world for personal drops, the recipient's world for broadcasts |
| `chatMessage` | Original chat/popup text, or a labeled Loot Tracker event summary when no message exists (message chosen by priority list if there are multiple) |
| `screenshot` | PNG game frame with MIME type `image/png`, not included for clan broadcast submissions |

Each drop gets a UUID `Idempotency-Key`.
The exact key, message, multipart body and screenshot are reused across retries.
The clan key is sent as UTF-8, unpadded base64 url in `X-Clan-API-Key-Base64`, preserving Unicode and whitespace.

Every submission includes `chatMessage` of the selected triggering message.
For matching pending claims, evidence is preferred in this order:

1. New collection log chat message
2. New collection log popup (in case message is disabled, but popup is not)
3. Valuable item message/Untradeable item message
4. Loot Tracker event
5. Other detection (unique messages, dialogs, obtain context)

Higher priority trigger replaces lower priority text while the claim is pending.
Equal priorities keep the first message. The original recipient, clan, item, world flags,
request key and the five second window remains unchanged is the text is replaced. Once the pending batch is taken
for screenshot capture (or a broadcast is sent), its proof is fixed across retries.

For chat notifications, the original Unicode, whitespace and RuneLite markup are preserved.
Popup-only collection notifications use the original popup's main text.
When the obtained item is detected with `Loot Tracker` and there is no message to send, the following is sent as `chatMessage`:
```text
RuneLite Loot Tracker event: Collector obtained <amount> x <item name> (item ID: <item id>), source: <item source>, type: <source type>.
```

For personally obtained items that qualify, the plugin captures the next rendered game frame after the detection tick.
Character name, clan name and world flags are captured at detection.

Clan broadcasts for other clan members send the triggering message with the username of the collector, clan name, item id, and world metadata of the collector, and never attach a screenshot for privacy.
Broadcasts for the local in player are ignored.

Triggers for the same recipient, clan, item and world flags are coalesced for five seconds from the first detection to filter out duplicate triggers.
Uploads use OkHttp asynchronously.

HTTP redirects are rejected to avoid forwarding credentials or screenshots to another URL.
The queue is held in memory for this plugin session. Disabling the plugin or changing the endpoint or clan key cancels queued work and active HTTP calls.
